# GPU G0—G2 改进验收（2026-10-15）

## 范围与实现

沿用CPU训练、GPU IVFFlat先检索、CPU float64重排及显式设备策略。G0修复候选完整覆盖后的空/不足K处理、GPU响应类型/范围/帧校验、隐式nprobe CPU回退和严格策略计划展示；GPU副本复用增加native就绪确认。G1缓存查询能力、复用客户端会话、分离控制/接入/排队/IPC统计。G2提供可选候选过滤+向量合并RPC，保留租约、revision、逐ID存在性/顺序检查、扫描名额和消息预算。

合并读取默认关闭，启动 `--fused-candidates` 后可逐SQL选择 `candidate_data_path='fused'|'separate'`。超大元数据按原ID顺序递归拆分，单行仍过大时使用原两步读取并标记mixed；这不是设备或质量回退。使用方法见 [GPU说明](../gpu-search.md)。

本轮没有上线生产批调度、批内独立取消、二进制/共享内存IPC、自动设备选择、持久索引分发、多GPU、GPU先过滤或训练。原有活动取消/超时仍可能回收整个worker，其他GPU副本及等待请求失效。

热会话每并发工作线程复用一个SessionClient，选库/预热完成后计时；并发1/4/8。三种冻结负载：1万/10万×128维、属性独立分布、10%过滤/K10及10万100%/K100。每组500个不同留出查询重复三次，CPU/GPU采用相同显式参数，交替执行顺序；变体顺序固定，因此温度与时序漂移仍是限制。

GPU答案与冻结结果比对，所有查询校验数量、过滤与float64距离。没有利用这些已见留出数据调ANN参数；这是传输和会话回归，不是新独立质量校准。原60组36通过/21不支持/3完整性失败的范围保持，不借CPU回退扩大纯GPU覆盖。

P50置信区间按查询跨重复聚类bootstrap（500次），不包含硬件/时间漂移。资源每5ms采样，可能漏峰；设备VRAM为整块显卡占用，包含桌面等其他进程。RPC字节是Protobuf序列化大小，不是网卡流量。各计时分量的中位数不可相加冒充同一请求的完整分解。

## G2选择依据：先优化存储数据路径

G1 cached的串行GPU native中位数约0.51/0.89/0.75ms，端到端24.63/26.89/37.41ms，native占比至多约3.4%；GPU队列约0.12ms，IPC约0.54—0.61ms。同期数据RPC中位数15.22/17.18/26.05ms，并发8接入耗时48.28—98.38ms。接入指标包含调度/反序列化，不是纯队列等待。

真实GPU batch1/4/8探测中，所有查询的候选集合、顺序和大于2^53的int64标签均一致。10万/K100的native摊销耗时从0.329ms（batch1）降至0.167ms（batch8），但batch8整批中位数为1.307ms；它没有排队、RPC和等待凑批成本，不能推出端到端同倍提速。

因此本轮不加0.5/1ms凑批等待、不重构生产取消调度，也不替换JSON IPC。保持单owner，优先实测合并候选RPC。代价是暂时放弃可能的少量native摊销收益；若后续负载/硬件显示GPU排队或native占比显著，应重新开启该阶段。

## 审查修复与后续限制

一次独立审查发现两项Important：普通SQL在会话设置GPU/显式数据路径后被误要求向量完成帧确认；复用检查把gpu_queue_full等准入拒绝当成worker故障。前者可能将已提交写入报告为失败，必须修复。9个轻量失败用例及2个真实RPC/GPU失败用例先复现，再修复；30项定向回归全部通过（29.87秒）。覆盖普通SELECT/CRUD/幂等状态、多GPU副本PID/generation保持、后续两表查询及死worker恢复。日志：results/gpu-review-red.log、results/gpu-review-green.log；轻量失败记录results/gpu-review-unit-red.log。

只对已确认副本缺失、worker故障或generation变化走恢复，队列满等错误向上报告资源不足；若dispatcher已退休旧generation，不重复重置。DATA_LOSS不进入设备恢复，普通SQL也不发送向量选项。

未新增第二轮审查，修复以先失败后通过的定向用例及全套回归验证。审查无Minor延期项。明确延期的生产合批/取消调度、G3—G5/P4及现有活动取消的影响见 [执行决策](../superpowers/plans/2026-10-15-gpu-improvements.md#实施决策与收口记录)。

最终全套命令：`OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 VECSTOR_REQUIRE_GPU=1 conda run --no-capture-output -n vecstor python -m pytest -q`，**565通过，143.84秒，无跳过**。日志results/gpu-improvements-final-suite.log。包括真实PTY两种读取路径、版本写入失效、旧读租约、协议损坏、扫描容量、GPU故障与文件隔离。
