# ANN 质量优化验收记录

日期：2026-10-14。实施分支 `codex/ann-recall-optimization`。保留默认 exact；CPU IVFFlat 通过显式质量配置启用，未合并、推送或接入 GPU。

## 质量与一致性

正式实验 `results/recall-calibration-20261014/` 覆盖 1 万/10 万行、128 维、独立/相关/带簇三种合成分布、0.1%/1%/10%/50%/100% 五档通过率及两条路径，共 60 组。每组 200 个校准查询选择参数，再使用 500 个独立留出查询评估；30,000 次留出查询全部为 ANN，无精确回退、空真值或结果不足。所有组平均 Recall@10≥0.95，最低 **0.9702**。原始结果、冻结参数、查询摘要和 bootstrap 区间保留在上述目录。

这是已测分布的组平均值，不是单查询保证，也不是任意真实 embedding 的保证。质量配置严格绑定完整 IndexKey、规范化过滤 SQL、K、路径与向量输入范围；写入使 revision 改变后，旧配置不能用于新快照。全桶检索仍标为 approximate，候选 float64 重排不意味着全局精确。

真实 RPC 验证各取 4 个留出查询、重复 3 次，共 720 次，逐项比对冻结 ID 与 float64 距离。它验证链路一致性，不替代每组 500 查询的质量统计：

- `results/recall-rpc-validation-20261014/`：显式参数对照、实际快照配置导出。
- `results/recall-profile-validation-20261014/`：服务加载配置后的 720 次对照。
- `results/recall-final-isolation-20261014/`：最终运行时优化后的 720 次对照；6 个 data-root 的目录/文件读取被拒绝，远程查询成功，服务进程全部回收。

## 成本与资源

`results/recall-rpc-costs-20261014/` 使用 10 万行独立分布、固定质量配置、热索引、localhost。比较标量/批量绑定和谓词计划缓存四种组合，覆盖两路径、四档通过率、并发 1/4/8，共 96 组、864 次查询；所有返回 ID 一致。每组 3 个向量重复 3 次，P95 只描述这次短实验，不构成尾延迟承诺。

下表为并发 1，旧标量绑定且关闭计划缓存，与默认批量绑定且开启缓存的端到端对照，单位 ms：

| 通过率 | 路径 | 旧 P50 / P95 | 优化 P50 / P95 |
| --- | --- | --- | --- |
| 0.1% | 先过滤 | 20.03 / 27.09 | 17.29 / 20.35 |
| 0.1% | 先检索 | 3520.95 / 3573.77 | 215.44 / 274.11 |
| 1% | 先过滤 | 36.02 / 45.86 | 26.76 / 35.16 |
| 1% | 先检索 | 490.87 / 500.80 | 51.46 / 68.28 |
| 10% | 先过滤 | 41.62 / 52.53 | 42.99 / 51.90 |
| 10% | 先检索 | 47.28 / 49.03 | 20.99 / 24.98 |
| 100% | 先过滤 | 156.51 / 170.02 | 147.88 / 160.49 |
| 100% | 先检索 | 30.29 / 36.44 | 24.91 / 36.90 |

0.1% 先检索组的 9 次请求存储 CPU 合计由 31.34 秒降至 1.41 秒，RPC 中位数仍为 55 次、Protobuf 字节仍为 295194。优化减少解析和绑定成本，没有减少候选需求或网络轮次。低通过率仍优先先过滤；没有实现自动路径选择，也不宣称所有场景提速。

整个成本矩阵采样峰值计算进程约 479.2 MiB、存储进程约 264.3 MiB，每 5ms 采样，可能漏掉瞬时尖峰。逐组基线 RSS、CPU、吞吐、RPC/字节见 report.json；256 MiB 是逻辑索引驻留预算，不是进程 RSS 硬限。

`results/recall-native-costs-20261014/` 对 nlist=128/256/512、训练迭代 10/20、每中心样本上限 256/512 做 12 组探索。各用 64 校准/128 留出查询及三档过滤率；36 组平均召回均达标，最低约 0.9578。构建约 207—1490ms，更大 nlist 或更长训练没有普遍优势。该探索不替代正式校准、不发布新默认配置；部分任务并行运行，计时不能视为独占机器的稳定基准。

## 工程修复与边界

- Faiss SWIG 参数直接赋值选择器会丢失所有权，原实现重复创建可造成约 5 MiB/次的 native 内存增长。改为保留所有权的关键字构造，子进程 RSS 回归先失败再通过。
- 选择器只在单次查询构建一次并跨候选轮次复用；仅证明全部 ID 与当前索引完全相等时省略。并发查询各自持有，不修改共享 nprobe。计划分开显示构建和 native 检索耗时。
- 候选 ID 使用绑定的 BIGINT[] 文本参数，保持完整 int64；存在性验证、顺序、deadline 和扫描名额不变。每条活跃租约最多缓存一份谓词计划，原 SQL 和生成 SQL 各不超过 64 KiB；结束租约释放。此处不是向量/结果缓存，P4 尚未完成。
- 校准恢复必须核对源代码及脚本摘要、数据指纹、查询划分和逐条记录对应的冻结参数；有审计理由的等价代码修复可以继续，算法变化应重新校准。独立最终审查发现的两个恢复校验问题已补失败测试并修复。
- 导出配置前重新校验实际数据指纹，防止误把历史质量证据绑定到已变化的数据。

## 执行裁定

3. 长校准被系统终止后在沙箱外恢复，保留原始中断记录；发现所有权泄漏后提前执行 Task 4 的正确性修复，审计等价源码变更，未改动冻结参数或留出集合。
