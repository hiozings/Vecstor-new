# P3 Faiss Execution Implementation Plan

> **For agentic workers:** 实施时使用 superpowers:executing-plans 与 test-driven-development。本文件记录 2026-10-13 的规划和后续实施；最终验证见 `docs/validation/p3-faiss.md`。

**Goal:** 在现有 v2 SQL 服务中提供版本匹配的 CPU IVF 近似检索、两条路径、候选扩展和可观察计划，保留默认精确与存算隔离。

**Architecture:** SQL 分类保持业务语法；SearchOptions 随请求传递；读租约确定索引键；计算侧索引 registry 和 executor 执行近似路径，存储提供快照导出/候选过滤，最终复用 float64 精确重排和回退。

**Tech Stack:** 现有 Faiss 1.12.0、NumPy、DuckDB、SQLGlot、gRPC/Protobuf、prompt_toolkit/Rich；CPU 必做，GPU 适配为可选后续项。

**Spec:** `docs/design/p3-faiss-execution.md`。

## Global Constraints

- 默认 exact + filter-first；没有新选项的旧请求不改变语义。
- 所有索引和 RPC 数据匹配同一 database_id/table_id/revision/schema_version/dimension/metric；不使用文件路径替代 RPC。
- 不重置总 deadline，不忽略取消，不以不足 K 的 ANN 候选冒充完整结果。
- 精确重排不等于精确召回；actual_mode 只能依据真实执行路径标记。
- 保留 P2 流名额、消息预算、幂等 CRUD 与 P2.5 读租约；不修改数据库 revision 粒度。
- 构建数据只来自读租约，训练不受当前 WHERE 限制；索引未验证完整不得发布。
- 实施前按 AGENTS 获得 Git 操作许可，在新分支开发，不直接修改 main。

## Review Focus

- UPDATE/DELETE/DROP 后索引仍可返回旧 ID：必须版本拒绝/回退，旧读可持有旧索引完成。
- Faiss -1、大整数 ID、float32 溢出和边界并列：不得变成错误向量读取或伪 exact。
- 候选扩展重复计数、nprobe 不增加、无进展循环：必须有确定预算和停止原因。
- 搜索路径暗中全量执行 WHERE 或每条查询重建索引：以真实 RPC/计划计数检查。
- 索引构建取消仍发布，或流占满线程阻塞取向量：进程清理、发布屏障与保留执行容量测试。
- EXPLAIN 执行了实际检索，ANALYZE 执行了两次：使用计数证明无隐含副作用。

## 模块划分

新增 `src/vecstor/index/`：`types.py`（IndexKey/配置/描述）、`faiss_backend.py`（Faiss 封装）、`registry.py`（只读索引与引用/预算）、`build_worker.py`（构建进程）。

新增 `src/vecstor/compute/vector_execution.py`（精确、预过滤、后过滤路径）、`query/search_options.py`（选项）、执行器内版本化计划 JSON（由 QueryExecutionPlan 消息承载，未单建 execution_plan.py）。将现有 `_vector` 有针对性地抽出并复用，不重构普通 SQL/CRUD。

修改 `storage/database.py`、`catalog.py`、`sql_service.py` 提供同租约导出与候选过滤；修改 proto、client、codec、shell 接入选项和计划；新增 `scripts/check_p3.py` 与 `benchmarks/p3/` 的可复现配置/实验入口。目录按实现需要建立，不先创建空模块。

- [x] 先写默认兼容、非法枚举/预算、会话隔离、exact/search-first 冲突及普通 SQL 不受选项影响的测试并观察失败。
- [x] 添加选项、能力接口、计划消息及 ReadLease.optional row_count；不改变旧字段编号。
- [x] 生成协议并验证 codec 的 schema/rows/complete、int64 和新增计划字段；老请求仍走 exact。
- [x] 验证：现有全套测试加 `tests/unit/test_search_options.py`、`test_p3_ui.py`、`tests/integration/test_p3_execution.py` 通过。

## Task 2 同快照数据接口

- [x] 先写大整数/乱序 ID、空表、分批、错误 token、丢批、重复 ID、不存在 ID 和语法非法测试。
- [x] 扩展 BeginRead 提供快照行数；实现专用导出，不拼造用户查询。
- [x] 候选过滤将候选 ID 的参数化条件与已校验 WHERE 组合，只检查该批 ID。
- [x] 验证跨扫描发生写入仍一致；取消/超时释放流和事务；新导出流不会占满所有工作线程。

- [x] 先写确定 seed 构建、自定义 ID、IDSelectorBatch、局部 nprobe、错误参数、空表/小表和巨大有限值测试。
- [x] 实现 CPU IndexIVFFlat，训练/构建在独立工作进程；导入数据覆盖计数和 ID 唯一性完整验证。
- [x] 实现默认 256 MiB/8 条目/1 构建任务约束、构建取消、发布屏障、索引引用与旧版本回收；相同 key 复用。
- [x] 集成 BuildIndex/ListIndexes/ClearIndexes RPC；构建过程固定租约，普通查询不隐式构建。
- [x] 验证并发旧读/新写/新索引、同名表重建、其他表写入保守失效、重启 registry 为空和无索引回退。

## Task 4 两路径与候选扩展

接口：`execute_vector(plan, lease, options, deadline) -> (SQLResult, QueryExecutionPlan)`；精确扫描保留当前行为，近似路径共享本次查询的候选累积与原始向量 float64 重排。

- [x] 先写 filter-first 选择器、search-first 无全量 ScanMetadata、跨轮去重、M<K/空结果、近似标签和候选充足但非全局精确的测试。
- [x] 实现两路径：小合法集合直接精确；否则 IVF prefilter；search-first 按候选 RPC 过滤，只取合法向量。
- [x] 按设计实现 L/nprobe 翻倍、唯一候选预算、6 轮上限和停止原因；全程检查同一 deadline。
- [x] 支持 fallback exact/error；错误版本、损坏响应和取消不能被普通回退吞掉。
- [x] 用真实 IVF(nlist=1) 构造前 100 个近邻不满足过滤的负载，验证第二轮扩展确实发生；另用多桶 IVF 测量 ANN 召回。

## 可选 GPU 扩展

必做 CPU 验收后，单独验证 GPU IVFFlat 的 ID 与每查询参数支持，先尝试 search-first。过滤选择器不支持时明确回退 CPU 或拒绝该组合，不能忽略过滤。记录显存、数据传输与 GPU 同步时间；不从 CPU 测试推断 GPU 正确。

GPU 参数上限和资源对象并发规则必须以当前安装版本实测为准。本任务不阻塞 P3 CPU 交付，也不把 CPU 构建能力标为 GPU 业务功能。GPU 索引持久化仍属于后续 P4。

## 顺序与完成条件

Task 1 → 2 → 3 → 4 → 5 → 6；Task 5 的纯展示原型可在协议固定后提前，但只展示模拟计划不算执行器完成。

检查点 A：版本正确的索引构建/复用，不改变旧 SQL 结果。检查点 B：两路径和扩展可独立验证。检查点 C：界面、计划、数据变更和隔离全链路通过。任何检查点失败都不进入性能结论阶段。

规划阶段（实施前）只完成代码接口梳理、Faiss 官方资料核对和内存 API 探针；当时没有实现 P3、安装依赖、建立索引文件或执行 Git 操作。Faiss 探针结果：1.12.0 支持 CPU IDSelectorBatch、局部 nprobe 和 int64 IDs，后续仍需上述业务级验证。
