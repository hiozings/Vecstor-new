# P2 gRPC Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans and test-driven-development; execute the checkboxes in order.

**Goal:** 独立存储/计算 gRPC 服务与 P1 一致，并在计算进程无权读取存储目录时通过验收。
**Architecture:** 固定快照、元数据过滤下推、向量分批传输、计算侧精确 Top-K。
**Tech Stack:** 现有 Conda、grpcio-tools、DuckDB、SQLGlot、NumPy；Linux Landlock 仅用于隔离验收。
**Spec:** `docs/design/p2-grpc.md`。

## Global Constraints

- P1 语义不变，保留独立基线；不新增环境依赖。
- 所有读取固定版本；无本地读取回退；不返回部分成功结果。
- 有总 deadline 和批次上限；应用自动重试为 0。
- 用户已允许检查 Git 并创建 P2 分支；在 `p2-grpc-storage-compute` 开发，不提交、推送或合并；保留原有 AGENTS 修改。

## Review Focus

- 错误版本、重复/不存在 ID、乱序或不完整响应必须失败。
- float32 线格式、int64 元数据、边界并列与空结果保持 P1 行为。
- gRPC deadline 不能在多批次间无限重置；断流取消不能返回部分结果。
- 隔离必须由内核执行且在创建线程前生效，不能只检查路径未传入。
- 存储停止后查询必须失败，防止缓存/共享文件掩盖网络依赖。
