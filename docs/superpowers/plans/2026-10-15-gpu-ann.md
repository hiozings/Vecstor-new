# GPU ANN 与 SQL 设备选择实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为现有引擎新增显式 GPU ANN search-first，用户通过每条 SQL 的 SETTINGS 选择设备，保持 CPU 行为和快照隔离。

**Architecture:** CPU 构建索引，常驻独立 GPU worker 保存克隆副本并串行处理设备任务。SQL设置逐请求解析合并，服务报告真实设备；无隐式训练和静默降级。

**Tech Stack:** 现有 Conda/Python、Faiss 1.12.0/CUDA、SQLGlot、gRPC/Protobuf；不预先安装新依赖。

**Spec:** [GPU 设计](../../design/gpu-ann-execution.md)。状态：2026-10-15 待评审，全部任务未实施。

## 全局约束

- 用户确认首期 GPU ANN；CPU 训练、精确基线与 float64 重排不变。首期GPU只承诺search-first；filter-first探测结果单独归档。
- 默认CPU/exact/filter-first；GPU必须明确请求，device_fallback默认error；旧质量证据仅用于CPU。
- 每请求固定MVCC租约/完整IndexKey；GPU worker不得读存储目录。现有256 MiB CPU逻辑预算不放宽。
- 建议GPU512 MiB逻辑索引/128 MiB scratch/256 MiB余量，8副本，1活动/8排队；这些都是可配置起点，不是RSS/VRAM硬限。
- Git操作须得到用户授权。实施前先处理现有未提交用户说明书，再创建 `codex/gpu-ann`；本计划不授权合并/推送，也不在规划阶段操作Git。

## 重点风险

- SQL字符串/注释含SETTINGS，以及同一输入多语句；必须使用tokenizer/AST，不以正则切分。
- GPU原生API可能拒绝或不实际应用selector，大候选可能触发native断言；独立进程探测先于服务接入。
- 显式GPU在缺副本/小集合/质量失败时静默走CPU；测试完成帧确认和设备回退状态。
- 超时终止worker使其他排队请求悬挂或旧handle复活；request_id/generation及所有失败通知必须测试。
- 大于2^53的ID和CPU/GPU浮点并列差异；保证ID不转double，最终重排契约不变。
