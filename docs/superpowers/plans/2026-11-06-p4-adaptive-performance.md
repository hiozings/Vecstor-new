# P4自适应性能退化修复实施计划

> 执行方式：沿用已授权的inline执行、定向失败复现、阶段提交；不合并、不推送。

**Goal:** 修复规划开销、成本覆盖与严重择路退化，并用新独立留出重新验收。

**Architecture:** 保持租约、版本、质量预算和设备选择边界；风险证据不随成本拟合失败丢弃，在线反馈区分方向性偏差与不确定性；对不可变规划对象和标量观测减少重复转换。校准拟合集、内部验证集和最终留出严格分离。

**Tech Stack:** 既有Python/NumPy/Faiss/gRPC环境，不新增学习框架。

**Spec:** 原设计docs/design/p4-adaptive-query-strategy.md及用户2026-11-06修复请求；本文件记录性能修复的实施补充。

## 已核实证据

- v1云端135配置/43470计时查询、9场景完整质量通过，性能18格均未通过；旧数据保存在原目录及完整tar归档，不覆写。
- case5搜索成本模型被拒后，failure_upper也变成unknown，策略固定选择慢filter-first。
- case6过滤成本模型被拒后，同样因风险未知选择慢search-first。
- case7第一条选择search-first，实测compute152ms、预测64ms；反馈扩大对称区间，第二条退回filter-first，后续偏差继续压低参考下界，造成路径锁定。
- case1存在拟合到最终评估的成本漂移，须改进采样并使用新数据验证，不能按旧留出直接调系数。
- 开发剖析热点为资格解析、冻结/展开对象、特征/回退估算及序列化；开发夹具不作为正式性能证据。

## 全局约束

保持500独立质量查询、200计时查询×3重复；模型误差中位数≤20%、P90≤40%；planner+feedback P95≤0.5ms且≤组P50的2%；延迟比P50≤1.10、P95≤1.20；明显差距组择路率≥90%。禁止在最终留出反复调参，禁止以重试洗掉失败。新种子预定20261106，生成后与v1全部查询摘要排重。

## T1 风险与成本证据分离

- [ ] RED：成本不可用不能抹除匹配预算的低失败率；真实失败观测和候选扩展不足仍提高风险。
- [ ] 严格解析独立风险证据/成本可用状态，保留原始失败拟合指标；旧配置兼容，不把不可用成本视为0。
- [ ] 相关策略解析、纯选择器、质量资格及RPC回归通过后提交。

## T2 反馈与路径锁定

- [ ] RED：重放case7同类偏差序列，不能因一次慢样本永久锁定慢路径。
- [ ] 有界历史内区分有符号偏差与残差；保持失效、TTL、取消回滚、EXPLAIN只读和风险优先级。
- [ ] 用独立合成测试验证正负漂移、离群样本、路径未被选择及版本更替；阶段提交。

## T3 规划热路径

- [ ] 针对剖析热点减少不可变对象重复冻结、字典展开、选项deepcopy和标量观测JSON往返。
- [ ] 若增加预计算或缓存，必须有容量边界，绑定版本/工件/SQL/K/预算/读选项/策略，逐查询保留质量范围和deadline校验。
- [ ] 功能/别名/可变数据拒绝测试及开发微基准前后对照；计时包含全部规划与反馈，不把开销移出计时。

## T4 校准与重新验收

- [ ] 排查冷暖分布、首次调用和采样顺序造成的漂移，模型只用拟合集训练，内部验证不参与预处理拟合。
- [ ] 保留所有拒绝桶；覆盖不足时明确降级，不改门槛或把失败成本证据冒充合格模型。
- [ ] 完整真实GPU/无PYTHONPATH回归后冻结源码，在云端用新种子重新pilot、校准、主矩阵及500独立auto留出。
- [ ] 补充代表性消融、并发/网络和双节点恢复；未测范围明确NOT_RUN。
- [ ] 下载证据、逐格分析新旧结果与资源成本，更新AGENTS/README/使用与验收文档并分阶段提交。

## Review Focus

风险与模型失配的边界；在线偏差反馈的选择偏差；缓存/预算变化时预计算失效；取消后观测回滚；校准与评估数据泄漏。性能不达标仍如实报告，不默认开启auto。

## 执行记录

T1已实现：导出器保留原始拟合与风险统计，cost_usable=false使延迟不可用，候选风险仍按匹配预算/快照和观测处理。2项RED复现；严格字段与旧配置兼容、纯选择器、资格、RPC和smoke/resume合计62项通过（30.43秒）。不代表成本覆盖或性能验收已通过。

T2已实现：有符号偏差校正预测中心，残差表示校正后的不确定性；首样本沿用0.2权重而非100%污染历史。反馈根据未校正预测处理TTL过期/并发更新，不把旧偏差误当新负误差。3项RED复现转通过，case7数值时序重放与相关测试共57通过（14.87秒）。历史仍受256条/300秒边界和取消回滚约束。

T3首轮：预冻结质量说明、保持每请求资格检查；去除标量deepcopy、通用观测展开，并缓存最多256个小型配置指纹（仅纯转换，不缓存数据或已选路径）。质量描述不可变与范围重新校验RED转GREEN，78项相关回归通过（11.30秒）。开发探针P95仍有波动，T3性能门槛待正式128维测量；不将调用次数减少直接宣称为达标。

T4诊断：同一旧数据副本上两次30查询、反向顺序的有/无5ms采样对照呈波动，无法认定采样为唯一根因。后续统一成本校准/评估的采样条件与验证时机，拟合目标仍为既有compute_elapsed_ms（已与在线反馈同口径），不可误改为客户端总耗时。

T4工具已实现：近共线求解不收敛与非负约束下错误删列均先RED复现；有界active-set以独立小维度穷举解验证。绝对/相对两个预定义目标用内部验证选优，不在最终留出选模型。交错采样、计时后oracle、与评估同资源采样、请求尝试日志与新旧查询排重已接入。综合111项通过（42.90秒）。旧内部校准诊断复算40→43/45合格，case6/7仍有拒绝桶；必须用新数据重新验收，不能用此复算替代。
